# План проведения Highlight Studio v10.6.0 Paid Beta

## Цель

Проверить не количество функций, а способность продукта самостоятельно пройти путь:

`установка → первый запуск → импорт → AI-анализ → Review Studio → рендер → повторный проект`.

## Когорта

Набрать 20–30 участников:

- 8–10 монтажёров стримеров;
- 8–10 небольших и средних стримеров;
- 4–6 нетехнических пользователей;
- минимум 3 компьютера без дискретной GPU;
- минимум по 3 конфигурации NVIDIA, AMD и Intel, когда оборудование доступно.

Не хранить персональные данные участников в репозитории. Реестр из `docs/templates/paid_beta_testers.csv` вести отдельно в закрытом хранилище.

## Материал

Проверить 30–50 VOD:

- игровые;
- разговорные;
- IRL;
- плохой или тихий звук;
- смешанная русская/английская речь;
- длительность от 30 минут до 6 часов;
- локальные файлы и Twitch VOD.

## Обязательные метрики

- завершение проекта без падения;
- успешность рендера;
- время до первого полезного результата;
- доля AI-кандидатов, оставленных пользователем;
- доля дублей;
- доля фрагментов с обрезанным контекстом;
- субъективная экономия времени;
- повторное использование продукта в течение 14 дней;
- количество обращений в поддержку на одного участника.

## Порог Paid Beta

- ≥ 95% проектов не теряют данные;
- ≥ 90% проектов завершают основной pipeline после повторной попытки;
- ≥ 98% запущенных рендеров создают корректный файл;
- ≥ 60% предложенных моментов пригодны или требуют только trim;
- < 5% дублей;
- < 10% явно обрезанных моментов;
- ≥ 50% экономии времени у монтажёров;
- минимум 5 пользователей готовы заплатить после trial;
- минимум 3 пользователя запускают второй проект.

## Stop-условия

Остановить расширение beta и исправить продукт, если:

- происходит потеря проекта или исходного файла;
- installer ломает существующую версию;
- лицензия блокирует доступ к уже готовым проектам;
- support bundle содержит видео, транскрипт, ключ или персональный путь;
- crash-free completion ниже 85%;
- пользователю регулярно нужен ручной терминал.

## Процесс одной сессии

1. Тестировщик устанавливает сборку без помощи разработчика.
2. Выполняет first-run wizard.
3. Обрабатывает первый VOD.
4. Отправляет structured feedback из приложения.
5. При ошибке создаёт support bundle.
6. Через 3–7 дней запускает второй проект.
7. Оператор вносит только агрегаты в benchmark-таблицу.

## Решение о переходе к массовой продаже

Переход разрешён только после проверки итогов по шаблону `vod_benchmark.csv`, Windows-матрице и журналу критических дефектов. Красивый интерфейс и зелёные unit-тесты сами по себе не являются основанием для массового релиза.
