# Web-режим, аккаунты и PostgreSQL

## Почему не удалён SQLite

SQLite не является «плохой» базой: для локального desktop-приложения с одним пользователем она проще, быстрее в обслуживании и работает без отдельного сервера. Поэтому desktop-режим сохраняет SQLite как локальный job-cache.

PostgreSQL включается в `web`-режиме, где одновременно работают разные пользователи и нужны транзакции, централизованные сессии, права, аудит и резервные копии.

## Что хранится в PostgreSQL

- пользователи и Argon2id-хеши паролей;
- сессии и CSRF-данные;
- роли пользователей;
- проекты и участники проектов;
- задания и их состояние;
- личные настройки пользователей;
- токены подтверждения email и сброса пароля;
- аудит действий и ограничения попыток входа.

Видео, аудио и готовые рендеры в БД не кладутся. Они находятся в persistent project storage. Для нескольких серверов project storage нужно заменить общим сетевым или S3-совместимым хранилищем.

## Роли

### Глобальные

- `admin` — управление пользователями, системной диагностикой и всеми проектами;
- `user` — доступ только к проектам, в которые пользователь добавлен.

### Проектные

- `owner` — полный доступ, удаление проекта и управление командой;
- `editor` — анализ, изменение монтажа, настройки и рендер;
- `viewer` — просмотр проекта и скачивание результатов без изменений.

Backend проверяет права независимо от интерфейса. Скрытие кнопки в React не считается защитой.

## Аутентификация

- Argon2id для паролей;
- opaque session token: браузер получает HttpOnly cookie, в БД хранится только SHA-256;
- отдельный CSRF cookie и обязательный `X-CSRF-Token` для изменяющих запросов;
- Secure/SameSite cookies в web-режиме;
- блокировка аккаунта после повторных неудачных входов;
- отдельное ограничение попыток по сочетанию IP и email;
- сброс пароля одноразовой ссылкой;
- подтверждение email, которое можно сделать обязательным через env;
- отзыв всех сессий после изменения или сброса пароля.

## Запуск

1. Скопировать `deploy/.env.example` в `deploy/.env`.
2. Задать домены, PostgreSQL password и секреты.
3. Настроить SMTP, если нужны письма подтверждения и сброса пароля.
4. Выполнить:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
```

Контейнер web-приложения автоматически выполняет `alembic upgrade head` перед запуском Uvicorn.

Первый зарегистрированный пользователь становится глобальным администратором. После этого публичную регистрацию можно отключить:

```env
HIGHLIGHT_STUDIO_ALLOW_REGISTRATION=0
```

## PostgreSQL backups

Compose запускает ежедневный `pg_dump` в отдельный volume и по умолчанию хранит копии 14 дней. Это не заменяет внешнюю резервную копию: production-сервер должен дополнительно выгружать backup volume в другое физическое хранилище.

## Ограничения текущей web-архитектуры

- обработка видео выполняется на одном processing node;
- очередь фоновых работ пока использует процессы приложения, а не отдельный distributed worker;
- project storage локальный для одного узла;
- SMTP и публичный домен нужно настроить отдельно;
- полноценный горизонтальный scale потребует общего object storage и отдельной worker queue.

Это рабочий многопользовательский web-режим для одного сервера. Он не заявлен как готовый кластер на десятки processing nodes.
