# Highlight Studio v10.9.0 — Web Accounts + PostgreSQL

## Цель версии

Превратить локальный однопользовательский инструмент в понятный многопользовательский web-продукт, не ломая автономный desktop-режим.

## Что реализовано

### Web-интерфейс и аккаунты

- отдельный красивый экран входа и регистрации;
- восстановление пароля и подтверждение email;
- отображение надёжности нового пароля и безопасное раскрытие поля пароля;
- HttpOnly-сессии и отдельная CSRF-защита;
- список активных устройств, завершение отдельной сессии и выход на всех устройствах;
- смена пароля с отзывом старых сессий;
- блокировка аккаунта и rate limit повторных попыток входа;
- административный список пользователей и журнал событий безопасности.

### Разграничение прав

Глобальные роли:

- `admin` — управление пользователями и системной диагностикой;
- `user` — доступ только к проектам, в которые пользователь добавлен.

Проектные роли:

- `owner` — полный доступ, удаление проекта и управление командой;
- `editor` — анализ, настройки, монтаж и рендер;
- `viewer` — просмотр и скачивание без права изменений.

Права проверяются backend middleware. Скрытие кнопок в React не считается защитой.

### PostgreSQL

В web-режиме PostgreSQL обязателен. SQLite допускается только в автономном desktop-режиме и в изолированных автоматических тестах.

В PostgreSQL хранятся:

- пользователи и Argon2id-хеши паролей;
- сессии и CSRF-хеши;
- роли и участники проектов;
- задания;
- аудит;
- личные настройки;
- токены подтверждения email и восстановления пароля;
- ограничения попыток входа.

Медиафайлы не кладутся в БД и остаются в persistent project storage.

### Надёжность и эксплуатация

- SQLAlchemy 2 и Alembic migrations;
- web-production отказывается запускаться на SQLite;
- production schema не создаётся через `create_all`, а требует `alembic upgrade head`;
- PostgreSQL connection pool и `pool_pre_ping`;
- ежедневный `pg_dump` с retention через Docker Compose;
- Caddy HTTPS и security headers;
- удаление проекта очищает project record, memberships и jobs;
- web-ответы скрывают серверные пути и секреты;
- локальный файловый браузер в web-режиме отключён.

## Честные ограничения

- в текущем инструментальном окружении отсутствуют Docker и живой PostgreSQL, поэтому реальный PostgreSQL-контейнер здесь не запускался;
- миграции скомпилированы PostgreSQL dialect, а вся web-логика проверена интеграционно на изолированной SQLAlchemy-БД;
- обработка видео пока выполняется на одном processing node;
- для горизонтального масштабирования нужны общие object storage и отдельная worker queue;
- SMTP, домен и TLS для production необходимо настроить отдельно.
