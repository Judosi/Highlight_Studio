# Highlight Studio 11.2.0 — отчёт об изменениях

## Диспетчер тяжёлых ресурсов

- `ResourceManager` теперь отслеживает владельца и глубину lease по потоку.
- Повторный захват того же ресурса владельцем не занимает второй физический слот.
- Конкурирующие потоки продолжают ожидать освобождения слота; отмена проверяется и при вложенном входе.
- В diagnostic snapshot добавлены `owner_count` и `lease_depth` без публикации идентификаторов потоков.

## Атомарный запуск задач

- `start_background_job` получил admission callback `prepare`, который выполняется после проверки лимитов, но до создания job.
- Endpoint одного Short сохраняет редакторские изменения только если именно его regeneration-job получил слот.
- Если worker-функция вернулась без terminal status, orchestration фиксирует `done` и 100%, поэтому UI/SQLite не остаются в ложном `running`.

## Переносимость и безопасность исходников

- Безопасный `source_video_relative_path` имеет приоритет над прежним абсолютным адресом. Копия проекта больше не читает VOD из исходной папки.
- Относительный `source_video_path` проходит ту же проверку корня и отклоняет traversal через `..`.
- Абсолютные внешние reference-пути сохранены для штатного desktop-сценария.

## Восстановление Shorts

- При сбое FFmpeg/валидации предыдущий canonical MP4 сохраняется.
- Если старый manifest отсутствовал или был неполным, новая строка восстанавливает `index`, `path`, `url`, размер, название и границы.
- Completion/freshness больше не получает пустой путь к сохранённому ролику.

## Сборка

- Версия синхронизирована как `11.2.0` во frontend, backend identity и desktop shells.
- Production frontend и React-исходник синхронизированы с identity 11.2.0; asset names получили release-specific marker `1120` для защиты от старого browser cache.
- Архив формируется только release-скриптом, содержит SHA-256 manifest и проходит отдельную проверку структуры/контрольных сумм.
