# Highlight Studio 11.2.3 — Micro AI Recovery & Result Integrity

## Исправленная первопричина

Центральный AI runtime правильно распознавал `requests.ReadTimeout` как временную транспортную ошибку, но после исчерпания внутренних попыток выбрасывал наружу исходное исключение. Pipeline ожидал `AITransportError`, поэтому не запускал warmup recovery. Вторая крупная попытка открывала circuit breaker, первый single-window rescue получал `circuit is open`, а все последующие batch заменялись fallback без обращения к AI.

В предоставленном проекте это остановило реальный Micro AI на 56 из 144 окон. Тем не менее анализ продолжился, выбрал 13 сцен общей длительностью 5:42 при цели 32 минуты и ошибочно сохранил статус `done`.

## Что изменено

- AI runtime выбрасывает нормализованный `AITransportError`, сохраняя transient-классификацию.
- После транспортного сбоя Micro AI выполняет ограниченный warmup recovery; успешный прогрев сбрасывает circuit breaker.
- Остаток текущего запуска автоматически переключается с крупного prompt batch на targeted single-window запросы.
- Если single-window запрос временно падает, модель повторно прогревается в пределах общего recovery budget.
- Недоступный batch больше не отключает навсегда весь остаток анализа: последующие batch получают отдельную попытку восстановления.
- Для автоматического профиля с 16 ГБ RAM или 4–6 ГБ VRAM логический Micro batch ограничен четырьмя окнами. Окна не удаляются — меняется только размер последовательной группы.
- Runtime-отчёт хранит configured/effective batch, список recovery events, факт adaptive mode и итоговое реальное AI-покрытие.
- При Micro AI coverage ниже 90% normal mode и ниже 100% strict mode анализ завершается возобновляемой ошибкой. `segments.json` не перезаписывается.
- Повторный запуск использует per-window checkpoints, поэтому уже готовые результаты не вычисляются повторно.

## Честность результата

Fallback остаётся допустимым для единичного изолированного сбоя, но серьёзно неполный Micro AI больше не может быть выдан как готовый монтаж. `analysis_health.json` получает outcome `incomplete_micro_ai`, точное покрытие, требуемый порог, `retryable=true` и число сохранённых прежних сегментов.

## Совместимость

Схема проекта и pipeline state не менялись. Пользовательские настройки и прежний ручной монтаж сохраняются. Для восстановления проблемного проекта достаточно открыть его в 11.2.3 и снова нажать анализ/продолжение.
