# Технический аудит Highlight Studio 11.2.2

## Гарантии исправления

1. `effective_max_final_segments` расширяет только вместимость итогового списка. Порог score/confidence/clarity, semantic classification, temporal fairness, overlap и dedup применяются как раньше.
2. Selection report отдельно хранит `configured_max_final_segments` и `effective_max_final_segments`; decision trace различает достижение целевой длительности и достижение фактической ёмкости.
3. Кэш длительности привязан к имени, размеру и `mtime` исходного файла. При несовпадении сигнатуры выполняется обычный `ffprobe`.
4. Быстрый revision path используется только если переданная клиентом ревизия совпадает с сохранённым серверным состоянием. При конфликте возвращается 409/428 и клиент обновляет данные.
5. Pending-состояние интерфейса очищается в `finally`, поэтому сетевой сбой не оставляет кнопку навсегда заблокированной.

## Ограничения

- Целевая длительность остаётся ориентиром качества. Если допустимых сцен недостаточно, результат может быть короче и отчёт покажет реальный недобор.
- Уже сохранённый ручной монтаж не перезаписывается при открытии проекта. Исправленный автоматический состав применяется после нового запуска анализа.
- Frontend production bundle синхронизирован с исходником релизным скриптом из-за недоступности внешнего npm registry в изолированной среде сборки; синтаксис и contract-тесты production bundle проверены отдельно.
