# Highlight Studio 11.1.0 — отчёт об изменениях

## Надёжность pipeline

- Добавлен `pipeline_state.json`: единый атомарный индекс стадий, прогресса, fingerprints, артефактов и ошибок.
- После аварийного закрытия running-стадии переводятся в recoverable `partial`/`pending`, а не маскируются под завершённые.
- Тяжёлые операции Whisper, Ollama и FFmpeg используют общий процессный ресурс `gpu_heavy`, поэтому несколько проектов не вытесняют друг друга из VRAM.

## Переносимость проектов

- Проект хранит абсолютную ссылку, безопасный относительный путь и filename hint.
- Resolver восстанавливает исходник после переноса каталога или компьютера, включая `input.*` и Twitch cache.
- Source/render fingerprints основаны на содержимом, а не на абсолютном пути и mtime, поэтому перенос не заставляет повторять многочасовой анализ.
- Схема проекта обновлена до версии 3 с идемпотентной миграцией.

## Локальный AI

- Таймаут загрузки модели/первого токена отделён от таймаута зависшего активного потока.
- Добавлен circuit breaker по provider/model: повторяющиеся transient-сбои временно останавливают бесполезные запросы и допускают recovery после cooldown.
- Warm-up сообщает runtime health тому же circuit breaker.

## Shorts

- В интерфейсе появился редактор каждого кандидата: название, границы, кадрирование и текст субтитров.
- Endpoint одного Short изменяет только выбранный кандидат.
- Новый файл сначала рендерится как fingerprinted pending, проходит ffprobe-проверку и лишь затем атомарно заменяет canonical output.
- При неудаче предыдущий корректный Short остаётся на месте; остальные Shorts не удаляются и не перерендериваются.

## Проверка релиза

Release gate включает backend regression tests, frontend contract tests, Electron security tests, Python compile/lint, проверку identity, обязательных файлов и содержимого итогового ZIP.
