# Highlight Studio 10.15.20

## Twitch Live

Исправлен сценарий, при котором запись текущего Twitch-эфира на 150 минут завершалась состоянием `error` ровно после 9300 секунд. Причина: FFmpeg использовал `-t` по медиатаймстампам, а внешний watchdog считал стеночное время и через `duration + 300` секунд принудительно завершал процесс. На HLS с разрывами/дис continuity эти два времени могут расходиться, поэтому уже пригодный `source_live.ts` ошибочно считался неудачной записью.

Теперь после достижения watchdog приложение проверяет `source_live.ts` через FFprobe. Если файл валиден и его длительность находится близко к выбранной цели, он принимается как готовый источник. Если запись действительно короткая, задача завершается понятной ошибкой с фактической и ожидаемой длительностью, а частичный файл сохраняется.

При повторном открытии/подготовке такого проекта приложение сначала проверяет уже существующий `twitch_cache/source_live.ts`. Если он почти достиг выбранной длительности, файл восстанавливается как готовый источник **до** запуска нового Streamlink/FFmpeg, поэтому многочасовую запись не нужно повторять.

## Безопасность диагностики

Сырой `subprocess.TimeoutExpired` больше не должен попадать пользователю для Twitch Live. Это предотвращает вывод полного временного Twitch playlist URL с access token в панели задач.

## Прогресс задач

Ошибка фоновой задачи больше не переводит прогресс искусственно в 100%. Сохраняется последний фактический процент (максимум 99%), поэтому статус «Ошибка» не выглядит как успешно завершённая операция.
