# Highlight Studio 10.15.8 — Manual Review Navigation

10.15.8 — отдельный релиз поверх 10.15.7. Предыдущие ZIP и папки не перезаписываются.

## 1. Ручной переход между этапами

После завершения Analysis приложение остаётся на текущем экране. Пользователь сам открывает «Монтаж» через боковое меню или кнопку «Перейти в монтаж». Автоматический выбор самого позднего этапа при открытии проекта заменён восстановлением последнего пользовательского этапа, если он доступен.

## 2. Правильный gate для «Монтажа»

Раньше Review/Montage блокировался при `candidates.length === 0`. Это смешивало два разных состояния: «анализ не завершён» и «анализ завершён, но кандидатов 0/они ещё не гидратировались». Теперь доступ определяется persisted `freshness.analysis_current` / `candidates_current` revision.

## 3. Защита от stale frontend state после long job

Лёгкий `progress-state` остаётся для экономии памяти во время многочасового анализа. При terminal state выполняется обязательная full-dashboard hydration; terminal state обязательно завершается полной hydration dashboard; в source также есть idempotent safety-effect против Windows/timer race.

## 4. Честное завершение One-click

Backend получает фактические `candidate_count` и `segment_count` из результата `analyze()`. Terminal status содержит эти значения и не сообщает «моменты найдены», когда кандидат 0.

## 5. Zero-candidate Review

Если analysis revision актуален, но кандидатов 0, «Монтаж» всё равно открывается. Вместо автоматического возврата назад показывается диагностическое empty-state с действиями «Обновить результаты», «Вернуться к анализу» и «Открыть диагностику».
